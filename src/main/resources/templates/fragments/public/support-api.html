Client API

Just Journal has a JSON API for writing clients. This page covers the endpoints a client needs to log in, post and read entries, and look up moods, locations and tags. The Software page lists existing clients, including the source for the Unix client, which uses this API.

Conventions

  • All endpoints are under https://www.justjournal.com/api/. Use HTTPS.
  • Send and expect JSON: Content-Type: application/json and Accept: application/json.
  • Authentication uses a session cookie. Log in once with POST /api/login, keep the cookie it sets, and send it with every later request. Don't save the cookie or the password to disk.
  • Errors usually come back as {"error": "message"} with a 4xx or 5xx status. 403 means you are not logged in or not allowed, 404 means the user or item doesn't exist, and 400 means the request was invalid.
  • Dates are ISO 8601, for example 2026-10-26T17:58:00.000+00:00.
  • Usernames are letters and numbers only and are not case sensitive.
  • Responses include an ETag. Send it back in If-None-Match to get a 304 Not Modified when nothing changed.

Logging in

RequestDescription
POST /api/login Body {"username": "...", "password": "..."}. Returns {"status": "JJ.LOGIN.OK", "username": "..."} and sets the session cookie, or 401 with "JJ.LOGIN.FAIL". If the account has two-factor authentication turned on, the password alone returns 200 with {"status": "JJ.LOGIN.2FA", "username": "...", "twoFactorMethod": "EMAIL"} (or "TOTP") and the session is not logged in yet; finish with POST /api/login/2fa on the same cookie.
POST /api/login/2fa Body {"code": "123456", "rememberDevice": false}, where the code comes from the user's e-mail, authenticator app, or recovery list. Returns JJ.LOGIN.OK and logs the session in, 401 JJ.LOGIN.FAIL for a wrong code, or 429 after too many wrong codes, after which the client must start again at POST /api/login. The pending login expires after ten minutes. GET /api/login/2fa reports whether a login is waiting and by which method; POST /api/login/2fa/resend mails a new code for the e-mail method.
GET /api/login Check the current session. status is JJ.LOGIN.OK with the username, or JJ.LOGIN.NONE.
GET /api/logoutEnd the session.

Entries

An entry looks like this:

{
  "entryId": 34079,
  "date": "2026-10-26T17:58:00.000+00:00",
  "modified": "2026-10-26T18:16:47.000+00:00",
  "user": "technews",
  "subject": "Hello",
  "body": "Entry text",
  "format": "MARKDOWN",
  "security": {"id": 2, "name": "public"},
  "location": 0,
  "mood": 12,
  "music": "",
  "tags": ["news", "linux"],
  "draft": false,
  "allowComments": true,
  "emailComments": true,
  "autoFormat": false,
  "imageId": 512,
  "imageAlt": "Tux at the keyboard",
  "imageUrl": "/EntryImage/512/display",
  "link": "https://example.com/article",
  "linkStatus": "READY",
  "comments": []
}
  • format is TEXT, MARKDOWN or HTML. HTML is cleaned on save, so scripts and unsafe markup are removed.
  • security may be sent as a number: 0 private, 1 friends, 2 public. Anything unrecognized is saved as private.
  • location and mood are ids from the lookup lists. Use 0 for none.
  • Tags are stored as lowercase letters, digits and hyphens, 30 characters or less. Tags you send are cleaned up first: Open Source becomes open-source, node.js becomes node-js, C++ becomes cplusplus, C# becomes csharp and accents are dropped. A tag left empty is ignored; one still longer than 30 characters is refused with a 400.
  • imageId, imageAlt and link attach a picture and a link preview; see Pictures and links on entries.
  • When posting, fields you leave out get the defaults: the current date, TEXT format, comments allowed, not a draft. Only body is required.
RequestDescription
GET /api/entry/{username}/size/{size}/page/{page} Entries newest first. page starts at 0 and size is 1–100. Entries are in _embedded.entryToList (missing when there are none) and the totals are in page: size, totalElements, totalPages, number. You get all of your own entries; for anyone else only public, non-draft entries.
GET /api/entry/{username}/page/{page} Same as above with 20 entries per page.
GET /api/entry/{username}/eid/{id} One entry. 403 if you aren't allowed to see it. This is the request that includes the entry's picture and link fields.
GET /api/entry/{username}/recent Ids and subjects of the latest entries, for a "recent entries" list.
POST /api/entry Create an entry (login required). Returns {"status": "ok", "id": "123"}.
PUT /api/entry Update an entry you own. Send the whole entry, including entryId. Returns {"id": "123"}.
DELETE /api/entry/{entryId} Delete an entry you own, with its comments. Returns {"id": "123"}.

Pictures and links on entries

An entry can have one picture and one link. Both are shown between the subject and the body, and carried in the feeds.

Pictures

Upload the picture first, then save the entry with the id you get back.

RequestDescription
POST /EntryImage Upload a picture (login required). Send multipart/form-data with the image in a part named file and, optionally, a description in alt. JPEG, PNG and GIF are accepted, up to 20 MB and 100 megapixels. Returns 201 with {"id": 512, "url": "/EntryImage/512/display"}. Every picture goes through a content filter: one it isn't sure about returns 202 with the same fields and a message, and only you can see it until it has been reviewed; one with nudity or sexual content is refused with 400. A file that is too large gets 413.
GET /EntryImage/{id}/display The picture resized to fit in 1024×1024, as shown on the entry.
GET /EntryImage/{id}The original file.
DELETE /EntryImage/{id}Delete a picture you uploaded.
  • On POST or PUT /api/entry, set imageId to the upload's id to attach it, 0 to remove the entry's picture, or leave it out to keep the current one. A picture can be on one entry only, and only on your own.
  • imageAlt describes the picture for readers who can't see it, up to 255 characters. Leave it out to keep the current description; send an empty string to clear it.
  • Replacing or removing a picture deletes the old one. An upload that isn't put on an entry within 24 hours is deleted, and you can have at most 10 uploads waiting at once.
  • Reading the entry gives imageId, imageAlt and imageUrl when you may see the picture. On your own entry, imageNotice says when it is still waiting for review.
  • Pictures follow the entry's security level: a private or friends-only entry's picture is only shown to the people who can read the entry.

Links

  • On POST or PUT /api/entry, set link to a URL to show a preview card for it. Send an empty string to remove the link, or leave it out to keep the current one.
  • The link is checked before anything is saved, and a link that fails refuses the whole save with 400 and a message. It must be http or https on the usual port, at most 1024 characters, not from a URL shortener, on a domain that exists and points only at public addresses, and not listed as unsafe (the site blocklist, Spamhaus DBL or Google Safe Browsing). Re-saving an entry with the link it already has skips the checks.
  • The preview is fetched in the background after the save: the page's title, description and Open Graph picture. Reading the entry gives link and a linkStatus of PENDING while that happens, then READY, or FAILED when the page couldn't be read after three tries. Until the preview is ready the card shows just the link. A link later found on an unsafe list becomes BLOCKED and is no longer shown to readers or in feeds; reading your own entry still gives it, with that status.
  • The preview's picture is at GET /EntryLinkImage/{id} once it has passed the content filter.

Comments

A comment has id, eid (the entry id), username, date, subject and body.

RequestDescription
GET /api/comment?entryId={id} Comments on an entry. Returns 403 and an empty list for private entries, friends-only entries when you aren't a friend, owner-only journals and entries with comments turned off. The entry's owner can always read them.
GET /api/comment/{id}One comment.
POST /api/comment Add a comment (login required). Body {"eid": 123, "subject": "...", "body": "..."}. The entry must allow comments.
PUT /api/commentEdit your comment. Include its id.
DELETE /api/comment/{id} Delete a comment you wrote.

Moods, locations and security levels

These lists rarely change. Load them once when the client starts.

RequestDescription
GET /api/mood All moods: {"id": 19, "parent": 0, "title": "Accepted"}. parent groups related moods.
GET /api/mood/{id}One mood.
GET /api/location All locations: {"id": 1, "title": "Home"}. Id 0 is "Not Specified".
GET /api/security Security levels: {"id": 2, "name": "public"}.

Search

RequestDescription
GET /api/search/{username}?term={text} Search one journal's public entries. Add &page=0&size=20 to page through results.
GET /api/search?term={text}Search public entries on the whole site, newest first, 20 per page. Add &page=1 for the next page.

Feeds and other protocols

  • Feeds of public entries: /users/{username}/rss (RSS 2.0), /users/{username}/atom and /users/{username}/json (JSON Feed).
  • Feeds carry an entry's picture once it has passed review, and its link unless it is blocked. RSS uses enclosure, media:content, media:thumbnail and atom:link rel="related"; Atom uses enclosure and related links with media:thumbnail; the JSON feed uses image, external_url and attachments.
  • Blogger 1.0 and MetaWeblog clients can post using https://www.justjournal.com/xml-rpc as the API URL. Clients that support Really Simple Discovery can find it at /rsd?blogID={username}.
  • Public journals and their public entries can be looked up from the fediverse, for example by searching for @{username}@justjournal.com on Mastodon. /.well-known/webfinger finds the account; /users/{username} and /users/{username}/entry/{id} answer with ActivityPub JSON when asked for application/activity+json, and /users/{username}/outbox lists public entries. When the site has the fediverse turned on, journals whose owners turned on the fediverse option can be followed from there.
