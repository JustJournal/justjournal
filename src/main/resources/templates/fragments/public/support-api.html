Client API

Just Journal has a JSON API for writing clients. This page covers the endpoints a client needs to log in, post and read entries, and look up moods, locations and tags. The Software page lists existing clients, including the source for the Unix client, which uses this API.

Conventions

  • All endpoints are under https://www.justjournal.com/api/. Use HTTPS.
  • Send and expect JSON: Content-Type: application/json and Accept: application/json.
  • Authentication uses a session cookie. Log in once with POST /api/login, keep the cookie it sets, and send it with every later request. Don't save the cookie or the password to disk.
  • Errors usually come back as {"error": "message"} with a 4xx or 5xx status. 403 means you are not logged in or not allowed, 404 means the user or item doesn't exist, and 400 means the request was invalid.
  • Dates are ISO 8601, for example 2026-10-26T17:58:00.000+00:00.
  • Usernames are letters and numbers only and are not case sensitive.
  • Responses include an ETag. Send it back in If-None-Match to get a 304 Not Modified when nothing changed.

Logging in

RequestDescription
POST /api/login Body {"username": "...", "password": "..."}. Returns {"status": "JJ.LOGIN.OK", "username": "..."} and sets the session cookie, or 401 with "JJ.LOGIN.FAIL".
GET /api/login Check the current session. status is JJ.LOGIN.OK with the username, or JJ.LOGIN.NONE.
GET /api/logoutEnd the session.

Entries

An entry looks like this:

{
  "entryId": 34079,
  "date": "2026-10-26T17:58:00.000+00:00",
  "modified": "2026-10-26T18:16:47.000+00:00",
  "user": "technews",
  "subject": "Hello",
  "body": "Entry text",
  "format": "MARKDOWN",
  "security": {"id": 2, "name": "public"},
  "location": 0,
  "mood": 12,
  "music": "",
  "tags": ["news", "linux"],
  "draft": false,
  "allowComments": true,
  "emailComments": true,
  "autoFormat": false,
  "comments": []
}
  • format is TEXT, MARKDOWN or HTML. HTML is cleaned on save, so scripts and unsafe markup are removed.
  • security may be sent as a number: 0 private, 1 friends, 2 public. Anything unrecognized is saved as private.
  • location and mood are ids from the lookup lists. Use 0 for none.
  • Tags are letters only, 30 characters or less.
  • When posting, fields you leave out get the defaults: the current date, TEXT format, comments allowed, not a draft. Only body is required.
RequestDescription
GET /api/entry/{username}/size/{size}/page/{page} Entries newest first. page starts at 0 and size is 1–100. Entries are in _embedded.entryToList (missing when there are none) and the totals are in page: size, totalElements, totalPages, number. You get all of your own entries; for anyone else only public, non-draft entries.
GET /api/entry/{username}/page/{page} Same as above with 20 entries per page.
GET /api/entry/{username}/eid/{id} One entry. 403 if you aren't allowed to see it.
GET /api/entry/{username}/recent Ids and subjects of the latest entries, for a "recent entries" list.
POST /api/entry Create an entry (login required). Returns {"status": "ok", "id": "123"}.
PUT /api/entry Update an entry you own. Send the whole entry, including entryId. Returns {"id": "123"}.
DELETE /api/entry/{entryId} Delete an entry you own, with its comments. Returns {"id": "123"}.

Comments

A comment has id, eid (the entry id), username, date, subject and body.

RequestDescription
GET /api/comment?entryId={id}Comments on an entry.
GET /api/comment/{id}One comment.
POST /api/comment Add a comment (login required). Body {"eid": 123, "subject": "...", "body": "..."}. The entry must allow comments.
PUT /api/commentEdit your comment. Include its id.
DELETE /api/comment/{id} Delete a comment you wrote.

Moods, locations and security levels

These lists rarely change. Load them once when the client starts.

RequestDescription
GET /api/mood All moods: {"id": 19, "parent": 0, "title": "Accepted"}. parent groups related moods.
GET /api/mood/{id}One mood.
GET /api/location All locations: {"id": 1, "title": "Home"}. Id 0 is "Not Specified".
GET /api/security Security levels: {"id": 2, "name": "public"}.

Tags, calendar and statistics

RequestDescription
GET /api/tagcloud/{username} Tags a user has used, with count and a type of TagCloudSmall, TagCloudMedium or TagCloudLarge.
GET /api/tagsEvery tag on the site, with counts.
GET /api/calendar/counts/{username} Entry counts per year: {"year": 2026, "month": 0, "count": 68}.
GET /api/calendar/counts/{username}/{year} Entry counts per month for one year.
GET /api/statistics/{username} {"username": "...", "entryCount": 68, "commentCount": 0}
GET /api/statisticsSite-wide totals.

Friends and favorites

RequestDescription
GET /api/friend/{username}A user's friends.
GET /api/friend/{username}/friendswith/{other} true or false.
PUT /api/friend/{friend}Add a friend (login required).
DELETE /api/friend/{friend}Remove a friend (login required).
GET /api/favoriteYour favorite entries (login required).
POST /api/favorite/{entryId}Add an entry to your favorites.
DELETE /api/favorite/{entryId}Remove an entry from your favorites.

Search

RequestDescription
GET /api/search/{username}?term={text} Search one journal's public entries. Add &page=0&size=20 to page through results.
GET /api/search?term={text}Search public entries on the whole site.

Feeds and other protocols

  • Feeds of public entries: /users/{username}/rss (RSS 2.0), /users/{username}/atom and /users/{username}/json (JSON Feed).
  • Blogger 1.0 and MetaWeblog clients can post using https://www.justjournal.com/xml-rpc as the API URL.
  • Journals can be followed from the fediverse. See /.well-known/webfinger and /@/{username}.
